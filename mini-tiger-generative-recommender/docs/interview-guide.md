# MiniTIGER 面试讲稿

## 简历描述

设计并实现面向 KuaiRec Big Matrix 的生成式多阶段推荐系统：融合内容特征与
SASRec Item Embedding 构建 Behavior-aware RQ-KMeans Semantic ID，使用
Transformer-GRU 自回归生成 Top-200 候选，再通过 SASRec 和学习式精排输出
Top-20；在 7,174 用户、9,438 视频上实现候选 Recall@200 `0.5619`，最终
Recall@20 `0.2137`、NDCG@20 `0.1048`，并实现零编码碰撞、全码本利用和
Exact/Beam 一致性诊断。

## 三分钟介绍

这个项目研究的是：能否把推荐问题从“在一万个 Item ID 中分类”，改成“逐级生成
带语义结构的商品编码”。

首先，我使用 KuaiRec 的内容特征和 SASRec 学到的行为 Item Embedding，构建三层
RQ-KMeans Semantic ID。索引包含容量约束、最小代价碰撞消解、Schema 和指纹，
最终 9,438 个视频没有编码碰撞，三级码本利用率都是 100%。

其次，Transformer 编码用户历史，GRU 解码器逐级生成下一视频的 Semantic ID。
解码只能沿商品目录 Trie 的合法前缀进行，因此不会生成无效商品。生成阶段取
Top-200，SASRec 只对候选精排，最后再用八维候选特征训练轻量融合器。

为了公平比较，我把生成模型做成约 163 万参数，与 SASRec 等容量；数据按时间
leave-last-two-out，验证集选 epoch，测试集只做最终报告。最终候选
Recall@200 是 `0.5619`，学习式精排后的 Recall@20 是 `0.2137`。

最后，我没有只汇报最好结果。全目录诊断发现 Exact 和 Beam=500 完全一致，
说明瓶颈不在搜索，而在第一级粗 Token 路由。损失加权与 SASRec 蒸馏都没有超过
原模型，这帮助我排除了无效优化方向。

## 常见追问

### 为什么这是生成式推荐？

模型按顺序生成 `c1 -> c2 -> c3 -> tail`，后一级概率依赖用户历史和前面已经
生成的 Token，不是多个独立分类头。

### 为什么使用 RQ-KMeans？

它逐级量化前一级未解释的残差，多个码字共同表达物品；相比普通树式 KMeans，
更适合形成紧凑、可组合的生成词表。

### 如何保证 Semantic ID 唯一？

最后一级在碰撞组内做最小代价匹配，极端情况下再使用 Tail Token。发布前强制
检查碰撞率、Token 利用率、最大桶容量和索引指纹。

### 为什么还需要 SASRec？

生成模型负责高效召回，SASRec 使用原始 Item ID 行为信号，对较小候选集进行
精排。两者负责的阶段不同，不影响系统属于生成式召回。

### 为什么 Recall@20 只有 0.21？

这是 9,438 商品、每个用户只有一个测试正例、并屏蔽历史商品的严格全目录评估。
指标应与相同数据切分和过滤协议下的基线比较，不能和小目录或不同协议直接比较。

### 最大瓶颈是什么？

第一级 Semantic ID 路由。正确第一级 Token 的预测明显比第二、三级困难；
Exact 与大 Beam 无差距，扩大 Beam 不能解决这个问题。

### 做过哪些失败实验？

尝试过提高第一级损失权重，以及用 SASRec 粗 Token 分布蒸馏生成模型。两者的
Recall@200 都下降到约 `0.539`，所以没有进入最终系统。失败说明更强教师不等于
学生能够吸收，下一步应考虑可学习的负载均衡路由，而不是继续调损失权重。

### 工业化还缺什么？

需要补充线上延迟和吞吐压测、增量 Item 索引更新、更多随机种子，以及百万级目录
下的分布式训练和 ANN/生成候选服务。
