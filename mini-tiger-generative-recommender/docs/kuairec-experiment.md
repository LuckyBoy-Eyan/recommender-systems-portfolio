# KuaiRec Big Matrix 重构说明

## 数据来源与任务

KuaiRec 是来自快手短视频平台、经过匿名化处理的公开研究数据。Big Matrix 原始
包含 7,176 个用户、10,728 个视频和 12,530,806 条带时间戳的观看行为。

本项目把任务定义为：

> 给定用户时间上更早的正反馈视频序列，生成其下一次正反馈视频的完整
> Semantic ID。

## 正反馈定义

Big Matrix 没有统一的点击标签，主要反馈是播放时长和观看比例。本项目默认要求：

```text
watch_ratio >= 0.7
并且
play_duration >= 5 秒
```

`watch_ratio` 可以超过 1，因为用户可能重复播放。阈值都由
`prepare_kuairec.py` 的命令行参数控制，后续应补充阈值消融。

## 全量准备统计

默认协议在官方数据上得到：

```text
原始正反馈事件：6,312,083
k-core 后事件：6,309,308
用户：7,174
视频：9,438
序列长度：最短 36，中位数 804，均值 879.47，最长 6,486
```

为了控制单机训练成本，模型配置只保留每个用户最近 300 条行为，并从训练前缀
中最多取最近 100 个预测点。原始准备文件仍保留全部 6,309,308 条正反馈，
因此可以通过配置扩大训练范围。

## 视频内容特征

Semantic ID 不使用随机视频编号，而是由以下静态内容生成：

- `item_categories.csv` 中的视频标签；
- caption 文件中的一级、二级、三级类别；
- caption、topic tag 和封面文字。

文本使用字符 1-2 gram TF-IDF，离散类别使用 one-hot；两者拼接后通过
TruncatedSVD 压缩为 64 维内容向量。另外，仅使用每个用户最后两个目标之前的
交互建立 item-user 矩阵，通过 TruncatedSVD 得到 64 维协同向量。二者拼接为
128 维并进行 L2 归一化。协同特征不会读取验证或测试目标。默认统计：

```text
内容维度：64
协同维度：64
文本词表：20,000
离散类别特征：417
具有内容元数据的视频：9,438 / 9,438
```

这套方案不依赖外部预训练模型，能够离线复现。进一步实验可以用中文文本
Embedding 替换 TF-IDF，但必须固定模型版本并记录特征生成协议。

## 无时间泄漏切分

每个用户按时间升序排列：

```text
[v1, v2, ..., v(n-2), v(n-1), vn]
```

切分为：

```text
训练前缀：[v1 ... v(n-2)]
验证目标：v(n-1)
测试目标：vn
```

选择超参数和最佳 epoch 只能看验证集；测试集只在确定模型后报告。

## Semantic ID

全量配置使用三层 `[64, 64, 64]` RQ-KMeans。特征先经过 96 维 PCA 白化和
L2 归一化；第一级量化特征，后续级量化前面码本没有解释掉的残差。生产环境
`rq_backend=auto` 优先选择 Faiss，当前无 Faiss 的环境自动回退到 sklearn。

每层分桶上限为 `ceil(N / K * 1.25)`。最后一级在共享前缀的碰撞组内使用
Hungarian 最小代价匹配，优先改到距离最近且未重复的 token；Tail Token 只保留
为极端目录的兜底。当前 9,438 个视频的索引预检结果：

```text
唯一 RQ 编码：9,438 / 9,438
原始碰撞率：0%
三层 token 利用率：100% / 100% / 100%
三层归一化熵：0.9891 / 0.9846 / 0.9611
三层发布编码 MSE：0.6831 -> 0.5627 -> 0.5105
末级去碰撞前 MSE：0.4995
每层最大桶：185（容量上限 185）
最小代价重分配：1,455 个末级 token
```

项目记录：

- 每一级实际使用 token 数；
- token 利用率；
- token 熵与归一化熵；
- 最大聚类桶；
- 完整前缀碰撞率；
- 最大碰撞桶。

索引发布时还会保存 PCA 参数、每层码本、物品编码、Schema 版本和内容指纹，
从而让离线训练、在线服务和回滚使用同一份不可变索引。

## 训练

模型结构保持：

```text
历史 Semantic ID
  -> 各级 embedding 求和
  -> Transformer Encoder
  -> 用户状态
  -> GRUCell 自回归生成多级 ID
```

KuaiRec 配置新增：

- 自动选择 CUDA、Apple MPS 或 CPU；
- AdamW 权重衰减；
- 梯度裁剪；
- 每轮验证；
- 按 Recall@20 选择最佳状态；
- patience=2 的早停；
- 保存训练 loss 与验证指标曲线。

## 推理

### 分块精确打分

Transformer 对每个用户只编码一次，随后对目录候选编码分块运行 GRU 解码器。
该结果作为精确评估基准。

### Trie 约束 Beam Search

先从全部有效商品编码建立：

```text
已生成前缀 -> 下一步允许的 token
```

Beam Search 只扩展 Trie 中存在的 token，因此：

- 不会生成目录外编码；
- 不需要给全部 9,438 个视频逐一打分；
- 可以通过 `beam_size` 控制效果与速度；
- 单元测试验证宽 Beam 与精确打分得到相同 Top-K 指标。

## Baseline

项目实现并比较以下模块：

1. Semantic ID：内容量化编码；
2. Random Hierarchical ID：层数和容量相同，但编码不含内容语义；
3. Popularity：只使用训练前缀统计热度。
4. SASRec：Item ID 序列基线与候选精排器；
5. Learned Reranker：在生成 Top-200 内学习融合生成、SASRec 与上下文特征。

Semantic ID 与 Random ID 使用相同模型容量；等容量生成模型与 SASRec 的参数量
差异低于 1%。所有模型使用相同时间切分与已看视频过滤协议。

## 局限

- 正反馈阈值仍需消融，不能把 0.7 当成唯一正确定义；
- TF-IDF 能复现但语义能力弱于稳定的中文预训练 Embedding；
- 尚未覆盖 GRU4Rec、BERT4Rec 等更多强序列推荐 baseline；
- Big Matrix 的曝光机制仍可能带来选择偏差；
- 全量训练成本远高于冒烟配置，应记录硬件和运行时间；
- Beam Search 需要报告相对精确打分的 Recall 差异与推理加速比。
