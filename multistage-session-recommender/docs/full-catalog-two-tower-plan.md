# 全量目录、双塔召回与精排升级方案（已实施）

> 该计划已经落地并继续演进到七路召回、Two-Tower V2 和 PLE V3。最终实现与结果见[完整实验报告](complete-experiment-report.md)。

## 目标架构

```text
因果可见全量商品目录
  -> Recent / Popularity / ItemCF / Item2Vec / Two-Tower
  -> 分路 Top-K、去重、来源诊断与动态配额
  -> 统一候选特征
  -> RRF / LambdaRank / Shared-Bottom
  -> clicks / carts / orders Top-20
```

“全量目录”指预处理不再按全局频次删除长尾商品。任一目标时间点的可召回目录仍只能
包含快照前已经出现的商品，以及当前 Session 已经交互的商品；未来目标不能提前进入目录。

## 阶段一：全量目录基线

- 使用 `prepare_retailrocket.py --full-catalog` 生成独立数据文件；
- 保留 Top3000 历史配置和结果，不用新口径覆盖旧指标；
- 对每个快照记录目录大小、候选覆盖率、平均候选数和因果审计；
- Item2Vec 使用稀疏梯度 SGNS 训练，并通过 FAISS-HNSW 查询验证会话，避免物化完整相似度矩阵；
- 比较四路召回在全量目录上的 Recall、独占命中、长尾覆盖、耗时和内存。

阶段验收：全量数据能够完成验证集流水线，所有候选属于因果目录，测试集保持关闭。

## 阶段二：双塔召回

### 用户塔

- 输入最近商品序列、行为类型、位置和时间间隔；
- 商品 ID Embedding 与行为 Embedding 融合；
- 第一版使用轻量 GRU/Attention 生成 Session 向量；
- 点击、加购、购买使用可配置权重。

### 商品塔

- Item ID Embedding；
- 训练窗口内的行为量、Session 覆盖、加购率和购买率；
- 接入 RetailRocket `item_properties` 与 `category_tree` 后，加入类目和属性表示；
- 输出与用户塔同维度并做 L2 归一化。

### 训练和检索

- 使用 In-Batch Negative，叠加热门负例和现有召回产生的 Hard Negative；
- 训练样本只来自训练时间窗口，验证和测试目标不参与参数学习；
- 为排序器生成训练候选时采用按时间划分的 OOF 模型，避免同一正样本既训练双塔又
  生成自己的召回分数；
- 小规模先用分块精确内积建立正确性基线，再切换 FAISS ANN；
- 每个快照只检索当时因果可见的商品子集。

阶段验收：单路双塔 Recall@K、独占命中、合并候选增量和分热门度结果均有记录；加入
双塔后若只增加候选量但不提高加权候选覆盖，则不进入正式链路。

## 阶段三：精排优化

- 保留 RRF 作为无训练基线；
- 增加 LightGBM LambdaRank，直接学习 Session 内候选顺序；
- Shared-Bottom 加入双塔相似度、双塔排名、来源交叉和内容匹配特征；
- 所有排序器使用相同候选和相同训练边界；
- 通过多随机种子和按 Session Bootstrap 报告差值置信区间。

阶段验收：先验证学习排序相对 RRF 的收益，再判断 LambdaRank 与 Shared-Bottom 的差异
是否超过随机波动。模型复杂度只有在稳定提升主指标时才增加。

## 评估纪律

- 当前历史测试集已经打开，不用于新结构选择；
- 全量目录、双塔结构、负采样和精排参数只看验证或滚动回测；
- 新方案冻结后再建立新的最终评估口径；
- 每次实验保存数据指纹、配置、随机种子、目录统计、耗时和候选明细。
